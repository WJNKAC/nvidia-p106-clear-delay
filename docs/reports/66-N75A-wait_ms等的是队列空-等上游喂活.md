> 2. **★ 但顺手对比 515 后发现：515 在这里的代码完全同构。** 所以「525 插入等待、515 轮询」这个说法**是错的**。
>    → **这个队列处理器不是 3 倍差异的来源。**

## 1. 第一个结论：等的是队列空

```asm
123ad30: mov  0x8e0988(%r15),%rsi   ; 队列读位置
123ad37: mov  0x8e0940(%r15),%rax   ; 队列写位置/边界
123ad3e: cmp  %rax,%rsi
123ad41: je   123aef0               ; ★ 相等 = 队列空 → 去递减预算 → 睡
123ad47: movl $0x0,0x8e0d24(%r15)   ; ★ 有活 → 超时计数清零 → 处理命令
123ad52: mov  (%rsi),%eax           ; 读命令头
```

**`wait_ms` 等的是「环形队列从空变成非空」= 等上游（应用/主线程）投递命令。**

不是等 GPU 完成、不是等 fence。
→ **9.4ms 是"等下一批命令来"的间隔，与超时参数无关。**

### 1.1 完整控制流

```asm
; --- 队列空之后 ---
123aef0: mov  0x8(%rsp),%eax          ; 轮询预算
123aef8: sub  $0x1,%eax               ; 预算 -1
123aeff: jne  123af1a                 ; 还有剩 → 回去再查
123af05: mov  $0x19,%eax              ; 25
123af0a: movb $0x1,0x17(%rsp)         ; ★ 置「该睡了」
123af11: cmove 0x28(%rsp),%eax        ; [rsp+0x2c]==0 → 保持原超时值
123af16: mov  %eax,0x28(%rsp)         ; 否则 → 超时值改成 25

123af1a: cmpl $0x14,0x8e0d24(%r15)    ; ★ 超时次数 vs 20
123af22: ja   123b130                  ; > 20 → 放弃

; --- 三个判据 ---
123b2f0: cmpb $0x0,0x17(%rsp)         ; 判据1：「该睡了」
123b2f5: jne  123b309                  ; 是 → wait
123b2f7: mov  0x2c(%rsp),%eax
123b2fb: test %eax,%eax                ; 判据2
123b2fd: jne  123b32f                  ; !=0 → 短让出
123b2ff: cmpb $0x0,0x8e0dc8(%r15)      ; 判据3
123b307: jne  123b32f                  ; !=0 → 短让出
123b309: mov  0x8e0950(%r15),%rdi      ; ★ 同步对象 B
123b310: mov  0x28(%rsp),%esi          ; 超时值
123b314: call *0x2d0(%rbp)             ; ★ wait = cond_timedwait
123b31a: test %eax,%eax                ; ← N74 栈帧地址
123b31c: jne  123afb4                  ; 被唤醒 → 回去查队列
123b322: addl $0x1,0x8e0d24(%r15)      ; 超时 → 计数 +1
123b32f: mov  $0x4,%edi
123b334: call *0x280(%rbp)             ; 短让出(4)
```

### 1.2 唤醒端

```asm
1238d80: mov  (%rdi),%rdx
1238d95: mov  %rdx,0x8e0940(%rdi)     ; ★ 写「写位置」
1238dac: mov  0x8e0910(%rdi),%rdi     ; ★ 同步对象 B（与 wait 同一指针）
1238db3: call *0x2d8(%rax)            ; ★ signal
```

`0x1238db3` 正是报告 38 定位的"真正的 pair-B 唤醒者（846/s = 24.4 次/帧）"。

**同步对象是同一个**：初始化时 `123c3e2` / `123c3ea` 把**同一个 `%rax`** 写入 `0x8e0910`（signal 用）和 `0x8e0950`（wait 用）。

## 2. ★★★ 第二个结论：515 完全同构 —— 这推翻了「525 插入等待」的说法

用户让我对比 515。按报告 35 的 ctx 基准偏移（515 `0x55f080` ↔ 525 `0x8e0d00`，差 **`0x381c80`**）：

| 525 偏移 | 515 偏移 | 差值 | 对上？ |
|---|---|---|---|
| `0x8e0d24`（超时计数） | `0x55f0a4` | `0x381c80` | **✅** |
| `0x8e0950`（同步对象 B） | `0x55ecd0` | `0x381c80` | **✅** |
| `0x8e0dc8`（判据 3 的字段） | `0x55f148` | `0x381c80` | **✅** |

**三个偏移全部精确等于 `0x381c80`。**

### 2.1 515 的对应代码（`0xc81d40`–`0xc81e74`）

```asm
c81d40: cmpb $0x0,0x1f(%rsp)      ; 判据1（525 是 0x17(%rsp)）
c81d45: je   c81e61                ; ==0 → 去判据2
c81d4b: mov  0x55ecd0(%r13),%rdi   ; ★ 同步对象 B
c81d52: mov  0x28(%rsp),%esi       ; ★ 同一个栈偏移 0x28
c81d56: call *0x2b8(%rbx)          ; ★ wait = cond_timedwait（525 是 0x2d0）
c81d5c: test %eax,%eax
c81d5e: jne  c81af1
c81d64: addl $0x1,0x55f0a4(%r13)   ; ★ 超时 +1
c81d6c: jmp  c81af1

c81e61: mov  0x2c(%rsp),%eax      ; 判据2
c81e65: test %eax,%eax
c81e67: je   c81ec6                ; ==0 → 去判据3
c81e69: mov  $0x4,%edi
c81e6e: call *0x270(%rbx)          ; ★ 短让出(4)（525 是 0x280）

c81ec6: cmpb $0x0,0x55f148(%r13)   ; ★ 判据3（= 525 的 0x8e0dc8）
c81ece: je   c81d4b                ; ==0 → wait
c81ed4: jmp  c81e69                ; !=0 → 短让出
```

### 2.2 逐条对照表

| 项 | 515 | 525 | 一致 |
|---|---|---|---|
| **判据 1** | `cmpb 0x1f(%rsp)` | `cmpb 0x17(%rsp)` | ✅ 同义 |
| **wait 分支** | 判据1 非 0 → wait | 判据1 非 0 → wait | ✅ |
| **判据 2** | `[rsp+0x2c]` | `[rsp+0x2c]` | ✅ **同一栈偏移** |
| **短让出分支** | 判据2 != 0 → `call *0x270` 参数 4 | 判据2 != 0 → `call *0x280` 参数 4 | ✅ |
| **判据 3** | `ctx+0x55f148` | `ctx+0x8e0dc8` | ✅ 同义 |
| **判据3 分支** | ==0 → wait；!=0 → 短让出 | ==0 → wait；!=0 → 短让出 | ✅ |
| **wait 槽** | `0x2b8` | `0x2d0` | ✅ 槽号平移 `0x18` |
| **短让出槽** | `0x270` | `0x280` | ✅ 槽号平移 `0x10` |
| **超时参数** | `[rsp+0x28]` | `[rsp+0x28]` | ✅ **同一栈偏移** |
| **超时计数** | `0x55f0a4` | `0x8e0d24` | ✅ |
| **超时上限** | `cmpl $0x14`（20） | `cmpl $0x14`（20） | ✅ |
| **超时后 +1** | `addl $0x1` | `addl $0x1` | ✅ |

**→ 两版在这个函数上完全同构。515 也调 `pthread_cond_timedwait`，也有三档判据，也是超时上限 20。**

### 2.3 这推翻了什么

**报告 37 的原话**：

> 唯一分叉在"notify 之后队列仍然空"这一条边：525 在这条边上先 `call *0x2d0(%rbp)` = `wait_ms`，
> 515 是 `call *0x270(%rbx)`（参数 `$0x4`）后 `jmp` 回轮询。**不是"把自旋改写成睡眠"，是"插一次等待"。**

**现在看**：515 的 `c81d56: call *0x2b8` 就是 cond wait，`c81e6e: call *0x270` 是短让出。
**两条边两版都有，只是 515 把它们排在 `判据1==0` 之后、525 排在 `判据1!=0` 之后——是同一条边的正反写法。**

**→ 「525 插入 wait_ms、515 轮询」不成立。两版都 wait。**

（报告 37 的最终结论"不是等待策略的问题、而在上游只按帧喂活"**仍然成立**，但理由要改：不是"525 多插了等待"，而是**两版都等，等的东西也一样**。）

## 3. ★ 判据 3 的语义：`(积压计数 > 20)` —— 而且两版也同构

用户让我先做 A（零成本追判据 3 的写入点）。做完了，结论同样是"同构"。

### 3.1 525 的写入点 `0x1238174` 附近

```asm
1238166: sub    $0x1,%eax
1238169: mov    $0x64,%edx            ; 100
123816e: cmp    $0x64,%eax            ; 与 100 比较
1238171: cmovae %edx,%eax             ; 夹到上限 100
1238174: movq   $0x0,0x8e0d10(%rbx)   ; 清统计数组
123817f: add    %ecx,%eax             ; eax += ecx（调用者传的量）
1238181: cmp    $0x14,%eax            ; ★ 与 20 比较
1238184: mov    %eax,0x8e0da4(%rbx)   ; 存积压计数
123818a: movq   $0x0,0x8e0d18(%rbx)
1238195: seta   %al                   ; ★ al = (积压 > 20)
1238198: and    $0x40000,%r10d
123819f: mov    %al,0x8e0dc8(%rbx)    ; ★ 判据 3 的字段
12381a5: mov    %al,0x8e0e08(%rbx)    ; 也存一份
```

**语义**：`ctx+0x8e0dc8 = (积压计数 > 20)`

配合判据 3 的分支（`!= 0 → 短让出`）：

| 积压计数 | 判据 3 | 行为 |
|---|---|---|
| **> 20** | 真 | **短让出（`call *0x280` 参数 4）—— 忙轮询，不睡** |
| **≤ 20** | 假 | **cond wait —— 睡** |

**这是一个自适应策略：积压多时忙轮询（降延迟），积压少时睡（省 CPU）。**

### 3.2 515 的同一段（`0xc82de7`–`0xc82e26`）

```asm
c82de7: cmp    $0x64,%eax
c82dea: cmovae %edx,%eax
c82ded: add    %ecx,%eax
c82def: movq   $0x0,0x55f090(%rbx)
c82dfa: movq   $0x0,0x55f098(%rbx)
c82e05: cmp    $0x14,%eax             ; ★ 同样是 20
c82e08: mov    %eax,0x55f124(%rbx)
c82e0e: seta   %al                   ; ★ 同样 (值 > 20)
c82e11: and    $0x40000,%r10d
c82e18: mov    %al,0x55f148(%rbx)     ; ★ 写入判据 3
c82e1e: mov    %al,0x55f188(%rbx)
c82e24: je     c82e2d
c82e26: movb   $0x1,0x55f08c(%rbx)
```

**逐条同构。** 唯一差别：525 把两条 `movq $0x0` 分别排在 `add` 前后，515 排在 `add` 之后 —— **指令调度差异，不是逻辑差异**。

### 3.3 所以"何时睡"这个开关，两版一样

| 项 | 515 | 525 | 一致 |
|---|---|---|---|
| 积压上限 | `cmp $0x64`（100） | `cmp $0x64` | ✅ |
| 睡/让出阈值 | `cmp $0x14`（20） | `cmp $0x14` | ✅ |
| 判据计算 | `seta` → 写入 | `seta` → 写入 | ✅ |
| 判据字段 | `0x55f148` | `0x8e0dc8` | ✅ 差 `0x381c80` |

**→ 连"什么时候不睡"这个自适应开关，两版也是同一份代码。**


## 4. 那么 3 倍差异在哪？

既然这个队列处理器同构，`T_land` 的 20.40 vs 1.29ms（报告 60）差异**不在这里**。

| 可能 | 状态 |
|---|---|
| 队列处理器的等待策略 | **❌ 本报告排除**（两版同构） |
| primus 用户态 4 个可动点 | ❌ 报告 58/59 排除 |
| GLX 层（客户端+服务端） | ❌ 报告 60/61 排除 |
| ioctl 提交路径 | ❌ 报告 63 排除（同构、且只占 0.7%） |
| glcore 用户态 CPU（3.82ms 那部分） | ◑ 报告 64：86% 在 glcore 但无单一热点 |
| **等待时长本身（9.4ms/次）** | **◑ 唯一没在 515 上量过** |

### 4.1 现在最该问的问题是新的

```
两版代码同构 → 为什么 525 等 9.4ms，515 不等？
```

三个候选：

| 候选 | 判据 |
|---|---|
| **A. signal 频率不同** | 报告 38 在 525 上测到 846/s。**515 没测过** |
| **B. 队列填充速度不同**（上游投递慢） | 若 515 每帧投递更多命令，队列更不容易空 |
| **C. 等待次数不同**（525 进 wait 更频繁） | 若判据 2/3 的字段值不同，进入 wait 的概率就不同 |

**这三个都只能在 515 上量。** 而 515 需要换驱动。

### 4.2 一个零成本的替代

**判据 2、3 用的是栈变量 `[rsp+0x2c]` 和 `ctx+0x8e0dc8`/`0x55f148`。**
如果能静态确定这两个字段的**写入点**和**语义**，就能知道"什么时候会走 wait、什么时候走短让出"。

- `ctx+0x8e0dc8` 在 525 有 5 处引用：
  - `123819f: mov %al,0x8e0dc8(%rbx)` ← **写入，`%al` 是某函数返回值**
  - `1237eb3` / `1238426`: `cmpb $0x0,...` ← 读
  - `1238312: movzbl ...` ← 读
  - `123b2ff` ← 本函数的判据 3
- `[rsp+0x2c]` 需在函数入口追

**这是一个纯静态的下一步，而且能直接回答"为什么 525 更容易进 wait"。**

## 6. 下一步

**静态已经挖到底了。** 这个队列处理器——"等什么"、"何时睡"、"睡多久上限"、"信号与等待是否配对"——**四项全部两版同构**。

**唯一还没在 515 上量过的量是"等待本身"。**

| 选项 | 内容 | 代价 | 回答 |
|---|---|---|---|
| **A（推荐，需换驱动）** | 给 515 补同一套测量：`/proc` utime、`wchan` 采样、futex uaddr、gdb 栈 | 需换驱动（~15min） | **515 的渲染线程等不等？等多久？** ← 现在这是唯一能定案的 |
| B（零成本） | 静态对比两版 `0x1238d80`（投递+signal）的**调用者数量** | 零成本 | signal 频率差异从哪来（但频率是运行时量，静态只能看调用点数量） |
| C（零成本） | 在 525 上做 STOP 实验：`kill -STOP` 渲染线程 0.5s，看主线程/上屏线程是否崩溃 | 一次 2s 采集 | 验证"渲染线程是瓶颈"这个前提是否成立 |

**建议 A**。因为已经排除到只剩"等待时长"这一个未测量。

### 6.1 一个必须承认的可能

如果 515 上也测出"渲染线程 87% 在 futex"、也是同一个 `wait_ms`，那么：

**3 倍差异就不在"等"上，而在"等之前做了多少事"或"队列被填得多快"。**

那意味着案子的性质变了：**不是"525 某个地方慢了"，而是"525 让应用侧的整体节拍慢下来"**——这与报告 37 的"上游只按帧喂活"同一个方向，但职责落在**驱动让应用跑多快**上。

**这个结论如果成立，就没有单点可改，只能换驱动或换硬件。**

### 7.1 方法论（四条，已入技能库）

1. **"等什么"要读条件表达式本身。**
   `cmp 读位置, 写位置; je` 三条指令定死"等队列非空"。
   报告 35 看过这段但看的是"路径分叉"，没看"比较的是哪两个字段"。

2. **★ 下"某版本特有"的结论前，必须去另一版同一位置核实。**
   本轮差点把"525 在队列空时插入 wait"当成 525 特有的问题。
   **按 ctx 基准偏移换算后，515 的代码逐条同构**（三个偏移全部对应）。
   **判据：先算 base 偏移差，再看三条以上关键指令是否一一对应。**

3. **槽号平移是版本间最常见的"假差异"。**
   515 `0x2b8` ↔ 525 `0x2d0`（+0x18）、515 `0x270` ↔ 525 `0x280`（+0x10）。
   **同一个 vtable 的不同版本，槽号会整体平移，不能按槽号相同判"同一函数"。**

4. **`cmove` 形式的赋值 = "有条件地保持原值"。**
   `mov $C,%eax` + `test` + `cmove 原值,%eax` + `mov %eax,目标`
   = "条件成立则保持原值，否则改成 C"。**别把 C 当成无条件常量。**
