## 1. N103-B 审计结果：580 的 358fps 与 525 的 64fps **不是同一把尺子**

### 1.1 两次用的命令不一样

| | 报告 07（580.126.18） | 报告 93（525.116.03） |
|---|---|---|
| 命令 | `vkmark -s 1920x1080 --winsys xcb -p immediate -b :duration=20` | `vkmark -D <UUID> -p immediate -b clear:duration=3` |
| `-b` 参数 | **`-b` 后面没有场景名** ⇒ 跑**默认全套场景** | **只跑 `clear` 一个场景** |
| 输出数字 | **358** | **64** |
| 是否指定设备 | 否（靠 `VK_ICD_FILENAMES` 只启 NVIDIA ICD） | 是（`-D $UUID`） |
| 分辨率 | 1920×1080 | **未指定**（走默认） |
| 采集时长 | 20 s（全套分摊） | 3 s |

**`vkmark` 不指定 `-b <scene>` 时跑全套场景并输出一个综合分（各场景的几何平均），
指定 `-b clear` 时只输出该场景的 fps。**

⇒ **358 是"全套综合分"，64 是"单场景 clear 的 fps"。报告 93 却把它们并列成"同一工具、5.4×"。这是错的。**

### 1.2 而且 580 那次的原始输出**没有留档**

我翻遍了 `analysis/onmachine/2026-10-24-runtime/` 与 `raw/`：

```
07-运行时归因-原生GL与Vulkan分流.md      ← 只有结论，无 vkmark 输出
strace-heaven-1080p.txt  perf-lbr-raw.txt  nvperf2.txt  e2_ths.txt   ← 全是 GL 侧的
raw/  ← 只有 futex/swapshim/probe 脚本
```

**没有任何一份 vkmark 的 stdout。** 连逐场景的 fps 都没有记录过——`grep -n "clear\|vertex\|shader\|texture"` 在归档版报告里 **0 命中**。

⇒ 358 这个数字**无法追溯到原始证据**，也不知道它到底是综合分还是某个场景的 fps。

### 1.3 那么"580 修好了 Vulkan"还站得住吗

**部分站得住，但不是我之前说的那个强度。**

唯一还能支撑它的推理是：**综合分 358 意味着全套场景都很快**。
vkmark 的综合分是各场景 fps 的几何平均；若五个场景里有任何一个卡在 64fps，几何平均会被拽到 200 上下。
所以 358 这个数**不太可能包含一个 64fps 的场景**。

⇒ 结论降级为：**"580 上 Vulkan 没有 525 那个 13.3ms 每帧地板"是弱证据支持的**，
但 **"5.6 倍"这个具体倍数不成立**——它把综合分和单场景 fps 相除，是错的。

**我在报告 101 §1、报告 102 §5.1 里都用了"5.6×"，这两处需要打折扣。** 已在原报告加注。

## 2. 那 525 的"Vulkan 慢"本身站得住吗

**站得住，因为它靠的是同机同命令的对照**：

| 对照 | 命令 | 结果 | 有效性 |
|---|---|---|---|
| P106 vs Intel 核显（**同一时刻、同一条命令、同一个 DISPLAY**） | `-D <UUID> -p immediate -b clear:duration=3` | **64 fps vs 4747 fps（74×）** | ✅ **完全有效** |
| P106 不同分辨率（同命令） | 同上，`-s` 变 | 320×240 = 75fps/13.33ms；1080p = 64fps/15.63ms | ✅ 有效 |
| P106 不同场景（同命令） | `clear` / `vertex` | 64 / 66 fps | ✅ 有效 |

**⇒ "525 下 P106 的 Vulkan 有一个 ≈13.3ms 的每帧固定项"这个结论是硬的**（同机同命令，且与分辨率几乎无关）。
**⇒ 但"580 没有这个固定项"这个对照是软的**（跨命令、跨版本、无原始日志）。

## 3. 缺口清单：3 版本 × 2 API 的六格，实际只有 4.5 格

| | GL（Heaven 1080p） | Vulkan（vkmark） |
|---|---|---|
| **515.105.01** | ✅ 101-138 fps（报告 79/05） | ⬜ **从未测过** |
| **525.116.03** | ✅ 30-31 fps（报告 79/93） | ✅ 64 fps `clear`（报告 93，同命令有效） |
| **580.126.18** | ✅ 30 fps（报告 05） | 🟡 **358，命令不同、无原始日志** |

**这一格空缺的代价很大**，因为它决定了两件完全不同的事：

| 515 的 Vulkan 若为 | 含义 |
|---|---|
| **≈300+ fps（健康）** | 515 是**两个 API 都健康**的版本 ⇒ 525 同时坏了 GL 和 Vulkan，是**一次双回归**；580 只修回了 Vulkan。⇒ "钉 515" 是全面正解。 |
| **≈64 fps（和 525 一样慢）** | Vulkan 慢**与驱动版本无关**，是"P106 无显示引擎 + PRIME 回传"的固有限制 ⇒ ① 515 的优势**只在 GL**；② **580 的 358 必然不可比**（否则 515/525 都慢、580 快，中间没道理）；③ 报告 07 的整个"Vulkan 分流"论证要重画。 |

**第二行如果成立，会连带推翻报告 07 的核心论证。** 所以这一格必须先填。

## 4. 实验方案（按成本从零到一）

### 4.1 第 0 步：零成本，不换驱动，现在就能做 ★ 建议先跑这个

在**当前的 525** 上，跑报告 07 用的**那条完整命令**：

```bash
export DISPLAY=:1 VK_ICD_FILENAMES=/etc/vulkan/icd.d/nvidia_icd.json
vkmark -L                                                    # 确认 0x10DE/0x1C07
vkmark -s 1920x1080 --winsys xcb -p immediate -b :duration=20 | tee /tmp/vk525-full.log
```

**判读**：

| 结果 | 含义 |
|---|---|
| **≈60-80**（和单场景 `clear` 同一量级） | 525 的 Vulkan **均匀地慢**，综合分/单场景的差异不是解释因素 ⇒ 报告 93 的"Vulkan 也慢"完全成立，`358 vs 64` 的差距是真的（只剩 580 待复核） |
| **≈300+** | **525 的 Vulkan 并非均匀慢**，只有 `clear`/`vertex` 这类极简场景被钳制 ⇒ 报告 93 的结论要**重新划定范围**，"每帧 13.3ms 固定项"这个模型可能只对特定场景成立 |
| **两档之间（100-250）** | 混合情形，需要看逐场景数字（这条命令会打出来） |

**这一步的价值**：它一次性判定了"综合分 vs 单场景"这个混淆到底有多大，**且不需要动驱动**。

### 4.2 第 1 步：填 515 那格（需要一次驱动切换）

```bash
# 装回 515.105.01 后
export DISPLAY=:1 VK_ICD_FILENAMES=/etc/vulkan/icd.d/nvidia_icd.json
# 两条都跑，一条对齐报告 07、一条对齐报告 93
vkmark -s 1920x1080 --winsys xcb -p immediate -b :duration=20 | tee /tmp/vk515-full.log
UUID=$(vkmark -L | sed -n '/Physical Device 1/,/Physical Device 2/p' | awk '/UUID/{print $3}')
vkmark -D $UUID -p immediate -b clear:duration=3   | tee /tmp/vk515-clear.log
vkmark -D $UUID -p immediate -b vertex:duration=3  | tee /tmp/vk515-vertex.log
```

### 4.3 第 2 步：复核 580（需要再一次驱动切换）

**用完全相同的两条命令**，得到 `/tmp/vk580-full.log` 与 `/tmp/vk580-clear.log`。
这才是"580 修好了 Vulkan"的合格证据。

### 4.4 最小可行集

若只想跑一次驱动切换：**跑 515 的两条命令**。
配合 §4.1 在 525 上已得的两条，再加上报告 93 已有的 525 `clear`=64，
就能把表格填到"只差 580 复核"的状态，而那一步可以用"综合分 358 不可能含 64fps 场景"这个弱推理先顶着。
