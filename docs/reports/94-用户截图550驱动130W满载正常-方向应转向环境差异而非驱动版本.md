### 2bis.1 本轮新查的硬件/链路特征（零成本，已排除与待查）

| 项 | 实测值 | 判读 |
|---|---|---|
| **ASPM** | `LnkCtl: ASPM Disabled` | ❌ **排除**。不是 PCIe 电源管理导致的唤醒延迟 |
| **PCIe 链路** | `LnkSta: Speed 2.5GT/s, Width x16`；`LnkCap: ... L1 <16us` | Gen1 x16 = 卡自身上限（`Device Max=1`） |
| **拓扑位置** | `[0000:00]-+-01.0-[01]----00.0 NVIDIA` | **CPU 直连（PEG），不在 PCH 后** ⇒ 不是插槽/hub 延迟 |
| **中断** | **`MSI: Enable+ Count=1/1 Maskable- 64bit+`；无 MSI-X capability** | ⚠️ **这块卡只有单个 MSI 向量**（P106 硬件简化）。且 `IRQ 36` 全压在 **CPU 3** |
| **MTRR** | `reg03: base=0x0c0000000 size=1024MB uncachable` —— 覆盖 3GB~4GB，**含 GPU BAR0(`0xf6000000`) 与 BAR1(`0xe0000000`)**；**全表无 write-combining 项** | ⚠️ **待查**：BAR 若为 UC 而非 WC，CPU 写显存/门铃会显著变慢 |
| 功耗上限 | `power.limit=120W`（min 60 / max 140），`SwPowerCap` 未激活 | ❌ 排除功耗墙 |
| GSP | `GSP Firmware Version: N/A` | ❌ 排除 GSP 固件 |
| 虚拟化检测 | `systemd-detect-virt = none` | 现在是**纯物理机** |

**两条新的可疑线（本轮新增）：**

1. **单 MSI 向量 + 单核亲和**：GPU 只有一个中断向量且集中在 CPU 3。
   正常 GPU 走 MSI-X 多向量、可分散到多核。若完成通知只能走这一条线，**每个批次的通知必须排队**，
   与"每批次 124µs 往返"的形状吻合。
   **但注意**：VFIO 直通时 guest 看到的中断能力由 QEMU 决定，**可能与物理机不同** ⇒ 这正好能解释环境差异。
2. **BAR 的 memory type**：MTRR 把 3~4GB 整段标成 `uncachable`，全表无 `write-combining`。
   若驱动本应给 BAR1 设 WC 却退化成 UC，CPU 侧写门铃/命令会慢一个量级。
   **这条要查 PAT 的实际 memtype**（`/sys/kernel/debug/x86/pat_memtype_list` 本轮只看到 write-back 项，
   未看到 GPU BAR 段，可能被 debugfs 截断或驱动用 io_remap 绕开）。

## 3. 结论修正（这是本轮最重要的部分）

### 3.1 我之前"停在 515"的推理链，前提是错的

我一直在证明的是：**525 相对 515 有一个可测的性能回归**（121µs/对 vs 0.03µs/对，4000 倍），
并据此把结论写成"515 是分界、回退到 515"。

**但"有回归"不等于"该换 515"。** 中间漏了一个必须验证的分支：

```
525 比 515 慢  ──┬─→ 若所有 525+ 都慢 ⇒ 版本回归 ⇒ 换 515 或修驱动
                 └─→ 若只有"本机配置 + 525"慢 ⇒ 环境问题 ⇒ 换 515 只是碰巧绕开
```

**用户给的证据落在第二条分支：**
- 图上 **550.90.07 在"同一台硬件 + PVE"下 130W / 99% util 正常**；
- 用户明确说 **525/535/570 在 vGPU 下都没有性能回退**。

⇒ **"525+ 全线回退"这个前提不成立。** 那"换 515"就**不是唯一解，甚至可能不是解**——
它只是在一个被环境弄坏的配置上，恰好换到一个没被弄坏的版本。

**但我要如实标注一个尚未分开的点**：2 年前那次是 **PVE + 550**，两个变量同时变了。
所以"550 好"与"PVE 好"目前**无法区分**，必须做 N104-A 分开。

### 3.2 真正该追问的变量：**为什么本机 MSI 上 GPU 只有 48~64W**

已排除（累计，均为实测）：

| 候选 | 排除依据 |
|---|---|
| 功耗墙 / vBIOS Rated TDP（报告 01 H1/H2） | 实测 `power.limit=120W`（min 60/max 140），`SwPowerCap` 未激活；报告 04 测到 79W |
| GSP 固件 | `GSP Firmware Version: N/A`（未加载） |
| 降频 / 过热 | 满频 1911MHz、37~48°C、无限流标志 |
| PCIe 带宽 | Gen1 x16 是**卡自身上限**（`Device Max=1`），且 Vulkan `clear` 场景在 320×240 也只有 75fps ⇒ 与带宽无关 |
| 合成器 / vsync / 显示管线 | 同机核显跑同一 Vulkan `clear` = **4747 fps**（报告 93） |
| GL 前端 / Vulkan 前端 | 两个前端都慢（30fps / 64fps）⇒ 不在前端 |
| 内核提交次数 | 两版相同（≈10.5 次/帧），单次 11.2µs，不阻塞 |

**仍未被排除、且与"图上是虚拟化环境"直接相关的：**

| 候选 | 为什么现在最可疑 |
|---|---|
| **物理直通 vs 虚拟机内直通** | 图上 `Compute M: N/A` 提示虚拟化；本机 `none`。QEMU 的 PCIe root port / 中断路由会改变驱动的 doorbell/完成路径时序 |
| **PCIe 插槽与拓扑** | 图上 `03:00.0`、本机 `01:00.0`。若本机挂在 PCH 后（而非 CPU 直连），延迟特性不同 |
| **BIOS 侧 PCIe 设置**（ASPM / L0s / L1 / ACS） | 会直接影响 ioctl→中断→完成的往返延迟，正好对应"每批次 124µs 等待" |
| **内核版本** | 本机 `6.1.0-50-amd64`（Debian 13 上跑 6.1 内核，混搭）；报告 07 那台记的是 `6.12.111+deb13` |

### 为什么只有这一件

现在方程里有两个未知数（环境、版本），而**只有装 550 能一次分开它们**：

| 实验结果 | 结论 | 后续 |
|---|---|---|
| **550 + 物理机 → 130W / 高 fps** | **是版本**（525 特有） | 直接用 550；不必碰 PVE；"换 515"这条线可以彻底放弃 |
| **550 + 物理机 → 仍 48~64W** | **是环境**（物理机直装） | 版本线全部作废；转查中断/BAR/BIOS，或直接装回 PVE |

**成本可控**：`/var/log/dpkg.log` 证明本机 **2026-02-24 装过 `550.163.01-2`**，
这是"回到跑过的状态"，不是冒险。驱动包在 `drivers/550.144.03/`（.run），另有 Debian 源版本 550.163.01。

### 具体做法

```
1) 备好：drivers/550.144.03/NVIDIA-Linux-x86_64-550.144.03.run
   或 apt: nvidia-driver=550.163.01-2（dpkg 日志里装过的同版本）
2) 装完重启（会黑屏几分钟，需你在场）
3) 跑三条：
   nvidia-smi --query-gpu=power.draw,clocks.sm,pstate,utilization.gpu --format=csv -l1

4) 判据：
   n83a 每对 ≈ 0.03µs 且 clear ≈ 高 fps  → 版本问题，收工
```

## 6. 教训（已入技能库）

1. **★★★ 用户给的截图/日志是首要证据，必须逐字段抄录进报告**。
   这张图 2025-03 就存在，我在报告 05 只引了"535 功耗有问题"**一句话**，把
   `driver 550.90.07 / Compute M: N/A / 130W / Pdbus 03:00.0` 全部漏掉了。
   **漏掉的原因是我在"找支持自己假设的句子"，而不是"读完整个证据"。**
2. **★★ "A 比 B 慢" 不能直接推出 "应该换 B"**。必须再问一句：**"有没有第三方 C 是快的？"**
   本例 C = 550.90.07，它一直就在证据里。
3. **★★ 论证"版本回归"必须证明"该版本在别的环境下也慢"。**
   只在一种环境里观察到慢，结论只能是"这个环境慢"，不是"这个版本差"。
4. **★ 换驱动的成本要先查安装历史**。`/var/log/dpkg.log` 显示本机装过 550.163.01，
   说明这是"回到跑过的状态"，不是冒险 —— 这类信息能把高风险实验降成低风险。
