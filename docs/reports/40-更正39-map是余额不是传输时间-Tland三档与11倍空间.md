## 3. 报告 39 错在哪：把"余额"当成了"传输时长"

报告 39 的推理链是：

```
map = 91µs + 317.8µs/MB × bytes     →  317.8µs/MB = 3.15GB/s ≈ Gen1 线速
↓ 用这把尺去量 515 的 map=1070µs
8.29MB / 1.07ms = 7.75 GB/s         →  超 Gen1 上限 2.4 倍 → "物理不可能"
```

**错在第一步就把它当成"传输时长"了。** 守恒律说的是：

```
map = max(0, T_land − sleep)
```

在 `sleep = 0` 时（**N12 分辨率扫描正是这个条件**），`map = T_land`，
所以那个拟合 `317.8µs/MB` 是**对的**——它确实是传输速率，因为当时没有睡眠抵扣。

但 **515 的 1070µs 不是 `sleep=0` 条件下测的**。515 的 primus autosleep 稳态是 `sleep = 9 × map`，
所以它那个 1070µs 是**在已经睡了 9.63ms 之后的余额**：

```
T_land(515) = 9630 + 1070 = 10.7 ms     →  775 MB/s
```

**完全合理，一点都不"物理不可能"。**

> **教训**：这把"尺"只在 `sleep = 0` 的测量里成立。
> 一旦被测数据来自"先睡后等"的结构（autosleep、IIR、任何补等机制），
> 就必须先换算 `T_land = sleep + map`，否则会用余额去算带宽。

## 4. 正确的量：T_land 三档

| 场景 | T_land | 有效带宽 | **÷ 物理下限** | 来源 |
|---|---|---|---|---|
| **隔离 rb_lat5（525, LOAD=0）** | **2.62 ms** | **3164 MB/s** | **1.0×** | 本次实测 |
| **515 真实 primus** | **10.1 ms** | 821 MB/s | **3.8×** | 报告 29/30（D=10.1ms） |
| **525 真实 primus** | **29.4 ms** | 282 MB/s | **11.2×** | 报告 26（D=29.4ms） |

PCIe Gen1 x16 物理下限 = 8.29MB / 3.15GB/s = **2.63 ms**。

**三档读法**：

- **隔离环境 3164 MB/s ≈ Gen1 线速**（3.15 GB/s）→ **PCIe 传输本身没有任何问题**。
- **515 慢了 3.8 倍**，**525 慢了 11.2 倍** → **慢的是"落地时机"，不是"传输速率"**。

## 5. 理论收益：如果把 T_land 拉回下限

autosleep 稳态 `sleep = 9×map`、`D = 10×map`、`T_land = D`，所以 `map = T_land/10`、`D = T_land`。

| T_land | 稳态 map | D | fps = 1/D |
|---|---|---|---|
| 29.4 ms（525 现状） | 2.94 ms | 29.4 ms | **34**（实测 34.7 ✓） |
| 20 ms | 2.0 ms | 20 ms | 50 |
| 10.1 ms（515 现状） | 1.01 ms | 10.1 ms | **99**（实测 108 ✓） |
| **2.62 ms（物理下限）** | 2.62 ms* | 2.62 ms | **~380** |

\* 严格说 T_land 降到 2.6ms 时，IIR 会使 sleep 收缩到 ≈9×0.26=2.3ms，总量仍在 2.6ms 附近。
隔离环境实测上限 **359.7 fps**（报告 39 的 D_p50=2.78ms 换算），与 ~380 一致。

**→ 从 34 到 380 是 11 倍。这不是靠"少搬字节"能拿到的——1080p 的 8.29MB 是固定的。
只能靠"让这次拷贝不要被排在后面"。**

## 9. 方法论（已入技能）

1. **"map = 测得的等待时长" 只在 `sleep=0` 时成立**。任何"先补睡、再等"的结构，
   必须换成 `T_land = sleep + map` 才能横向比较。
2. **横向比较两个实现的"等待开销"之前，先确认两边的 pre-sleep 是否相同**。
   本例 515 与 525 的 map 差 2.6 倍，但这 2.6 倍**完全由 autosleep 的 9× 反馈决定**，
   不是"谁等得更久"。
3. **"低于物理下限"是一个强信号，但要先排除"它测的是余额"**。
   本例报告 39 差点把一个正确数据判成"不可能"。
4. **一旦发现某量"贴着物理下限"（1.0×）**，说明该通路本身没坏，
   问题在"调度/排队"。这时的优化目标应从"提高速率"改为"减少排队"——两者手段完全不同。
