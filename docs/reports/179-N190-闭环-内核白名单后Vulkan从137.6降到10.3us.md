# N190 — 闭环完成：打上内核白名单后，Vulkan 的 137.6 µs 降到 10.3 µs

**日期**：2026-10-31
**驱动**：580.178.04 / kernel 6.12.113 / P104-100 / PCIe Gen1 x4
**状态**：**内核白名单已打**（`nvidia.ko` 里 P104-100 只剩 1 处 = PCI device ID 表）
**意义**：这是 N186~N189 一路追下来的最后一环 —— **因果链闭合**。

---

## 0. 结论

**内核白名单就是答案。** 同一个探针、同一台机、同一驱动版本，只改了内核模块：

| 项目（长帧数 400） | 未打内核补丁 | **已打内核补丁** | 变化 |
|---|---|---|---|
| **Vulkan render pass 空操作** | **137.6 µs** | **10.3 µs** | **↓ 13.4×** |
| Vulkan clear 256² | 137.4 µs | 21.2 µs | ↓ 6.5× |
| Vulkan clear 1024² | 160.7 µs | 10.3 µs | ↓ 15.6× |
| Vulkan 1 draw 256² | 139 µs | 18.2 µs | ↓ 7.6× |
| **zink（GL→Vulkan）** | **142.6 µs** | **35.1~37.0 µs** | **↓ 3.9×** |
| 原生 GL（n=400，`-s`） | 21.8 µs | 21.8 µs | 不变 |
| Vulkan copy | 11.2 µs | 8.9 µs | 不变 |

**关键点：`10.3 µs` 正是 lavapipe（纯 CPU 软件 Vulkan）的量级（9.9 µs）。**
⇒ 打上内核补丁后，P104 的 Vulkan render pass 开销**回到了「正常实现」的应有水平**。

空 render pass 重复 5 次，全部 **10.3 µs**，零抖动。

## 1. 这如何收束前面的所有报告

| 报告 | 当时的结论 | 现在 |
|---|---|---|
| N186 | glcore 用户态补丁对 zink 无效（143.5→142.0） | ✅ 成立；且**内核补丁对 zink 有效**（142.6→36） |
| N187 | 原生 Vulkan 3D 每提交 ~139 µs | ✅ 成立；现为 10~18 µs |
| N188 | 成本是「每 render pass」，固定 ~137 µs | ✅ 成立；已打后固定部分消失 |
| N189 | P104 空 render pass 154 µs vs lavapipe 10 µs（15×） | ✅ **预言成真**：打上后 P104 = 10.3 µs |

N189 里写的预期是「若从 154 µs 掉到 ~10 µs 量级，则证明是受限 SKU」——
**实测 10.3 µs，与 lavapipe 的 9.9 µs 几乎相同。**

## 2. 三条路径的完整定位（现在可以画完整图）

```
                    ┌─ OpenGL 应用 ──→ libGLX_nvidia → glcore（GL pushbuffer）
                    │                                    ↑
  应用 ──→ 图形 API ─┤                              用户态 1 字节补丁可截断（N186：147→21.8）
                    │
                    └─ Vulkan 应用 ──→ libvulkan → eglcore（Vulkan 实现，perf 96%）
                                                         ↑
                                          用户态**找不到**可截断点（N188/N189 实测两处 je 均无效）
                                                         ↓
                                             全局表 0x2180900+0x2b8 运行时分发
                                                         ↓
                                              poll 100+ 个 /dev/nvidia0 等完成（N189 gdb）
                                                         ↓
  内核 nvidia.ko：受限 SKU 白名单 ← **只有这里能一次治好两条路径**（本报告）
```

- **用户态 glcore 补丁**：只覆盖 OpenGL（147 → 21.8 µs）
- **用户态 eglcore 补丁**：无效（两处 `je` 实测零变化）
- **内核白名单**：Vulkan 137.6 → 10.3 µs，且 Vukan copy 本来就没问题（11 µs）

## 3. 一个意外发现：zink 也治好了，但没到 21 µs

| | 未打 | 已打 |
|---|---|---|
| zink n=400 | 142.6 µs | **35.1~37.0 µs** |
| 原生 GL n=400（有用户态补丁） | 21.8 µs | 21.8 µs |

zink 走 Vulkan，所以内核补丁把它从 142.6 拉到 36 —— **降幅 3.9 倍，但没到原生 GL 的 21.8**。

剩下的 ~14 µs 应该是 zink 自身的 GL→Vulkan 转换开销（Mesa 那层）。
这符合预期：zink 不是零成本桥梁。

**同时也说明：内核补丁 + 用户态补丁可以叠，但用户态补丁只对 GL 生效。**

---

## 4. 原生 GL 为什么一点没变

| | 未打内核 | 已打内核 |
|---|---|---|
| 原生 GL n=400 | 21.8 µs | **21.8 µs**（三次重复完全一致） |

因为 glcore 的用户态补丁**已经在拦那条命令了**（`0xb51c82` 的 `jmp`），
内核白名单只是把同一个效果从上游实现了 —— **两者不叠加**。
这与项目历史结论（N174：「两个补丁互不叠加，内核补丁是治本」）完全一致。

**⇒ 如果只想治 OpenGL，用户态 1 字节补丁就够；要治 Vulkan，必须打内核白名单。**

## 6. 对用户的实践结论

| 你的程序走什么 | 需要什么 |
|---|---|
| OpenGL | 用户态 glcore 补丁（1 字节，最轻） |
| **Vulkan（DXVK / vkd3d / 原生 VK）** | **必须内核白名单** |
| 两者都有 | 只打内核白名单即可（用户态补丁变冗余） |

**这也回过头解释了 10-30 七日世界**：它走 DXVK（Vulkan），glcore 补丁在位仍 19 fps；
打内核白名单才到 60 fps。

## 7. 顺带记一个操作教训

本轮开始时探针全跑不了 —— **`/tmp` 被重启清空了**。
源码幸好已收进项目 `tools/static/`，从那里重编即可：

```bash
cd <项目>/tools/static
glslangValidator -V tri.vert -o /tmp/tri.vert.spv
glslangValidator -V tri.frag -o /tmp/tri.frag.spv
gcc -O2 -o /tmp/batchprobe batchprobe.c -lGL -lX11
gcc -O2 -o /tmp/vkdraw    vkdraw.c    -lvulkan
gcc -O2 -o /tmp/vkprobe   vkprobe.c   -lvulkan
```

> ⚠ 项目里的 `vkdraw.c` 曾漏同步一个改名修复（`ms` 与 `VkPipelineMultisampleStateCreateInfo ms` 重名），
> 本次已补上。以后改 `/tmp` 的副本要记得同步回 `tools/static/`。

另：`vkdraw` 用 `-d 0` 时 `per_pass` 会除以 0 不打印，**改看 `per_submit`**（`-p` 默认 1，两者相等）。

## 8. 复现

```bash
NV=/etc/vulkan/icd.d/nvidia_icd.json

# 关键三连（长帧数 400）
VK_ICD_FILENAMES=$NV VKPROBE_VID=0x10de VKPROBE_DID=0x1b87 ./vkdraw -n 100 -f 400 -w 20 -d 1 -e        # 空提交
VK_ICD_FILENAMES=$NV VKPROBE_VID=0x10de VKPROBE_DID=0x1b87 ./vkdraw -n 100 -f 400 -w 20 -d 0 -x        # 空 render pass ★
VK_ICD_FILENAMES=$NV VKPROBE_VID=0x10de VKPROBE_DID=0x1b87 ./vkdraw -n 100 -f 400 -w 20 -d 0 -r 256     # clear

# 对照（纯 CPU）
VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/lvp_icd.json VKPROBE_VID=0 VKPROBE_DID=0 ./vkdraw -n 100 -f 400 -w 20 -d 0 -x
```

预期（已打内核白名单）：`-x` 与 `-e` 都应在 10~20 µs 区间；未打时为 137 µs。
