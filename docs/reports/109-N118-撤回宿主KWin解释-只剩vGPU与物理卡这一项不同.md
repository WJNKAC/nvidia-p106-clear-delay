## 2. 把所有"相同项"划掉之后，只剩一项不同

| 项 | 真机（慢，30fps） | PVE guest（快） | 是否相同 |
|---|---|---|---|
| 硬件 | P106-100 + HD P4600 | P106-100 + HD P4600 | **相同**（同一台机器） |
| 桌面 | KDE（KWin） | **KDE（KWin）** | **相同**（用户指正） |
| 显示栈 | app → Xwayland → KWin → i915 → HDMI | **app → Xwayland → KWin → i915 → HDMI** | **相同**（显示栈直通进 guest） |
| 谁拥有核显 | 宿主 | guest（x-vga=1） | 不同，但**层数相同** |
| **P106 的身份** | **物理 PCIe 设备** | **vGPU（mediated device）** | ★ **唯一不同的实质项** |

**⇒ 差异只能在"P106 是 vGPU 还是物理卡"这一项上。**

## 3. 在真机上测到的那一项异常，正好落在这个位置上

真机 525 上唯一量到的、能解释 30fps 的异常：

```
n83a（pbuffer+FBO，不经过 present）：
  M1 基线（零状态变更） = 3.316 ms
  M3（切 program + draw）= 15.170 ms
  ⇒ 每对 118.5 µs，GPU 侧 ≈231k 周期（1911MHz）
```

```
Heaven 每帧 ≈ 268 对
268 × 118.5 µs = 31.8 ms  +3.3 ms 基线 = 35.1 ms  ⇒  28.5 fps ≈ 实测 29-30 fps
```

**账是闭合的**：真机的慢**完全**由这 118.5µs/对的提交惩罚解释，不需要 present 层参与。
而 primus（改 present 路径）对 Heaven 无效（30→29fps），也从反面证明 present 不是主因。

对照 515：**0.03 µs/对** —— 同一张卡、同一台机器，换个驱动就没了。

### 3.1 为什么 vGPU 上这项惩罚可能不存在（假说 H1）

```
物理直通：guest/host 的驱动 → MMIO 写 → 硅片 PGRAPH 真的重新 arming → 每批 ≈118.5µs
vGPU    ：guest 的 MMIO 写 → VM exit → 宿主 nvidia-vgpu-mgr 截获/排队 → 宿主 RM 代做
          ⇒ 宿主可以对**多个来源的提交合批**，把"每批一次的固定代价"摊掉
```

这也解释了用户最早的观察：**525/535/570 在 vGPU 下都不回退** —— 因为那项惩罚在 vGPU 上根本不存在，
与驱动版本无关。

**可被否证的预测**：如果哪天能在 vGPU guest 里跑 `n83a -M 1 / -M 3`，每对应该是 **≈0.03 µs 量级**（像 515），
而不是 118.5 µs。**若测出 118.5 µs，H1 就死。**

**但现在做不了**：客户机系统盘已不存在（`scsi0` 指的 WDC 500GB 已不在机器上）。

## 4. 这个结论对实际使用意味着什么

**真机上的性能只由一件事决定：每帧要付多少次"状态切换 + draw"的配对。**

| 手段 | 效果 | 依据 |
|---|---|---|
| **装 515** | 118.5µs → 0.03µs，Heaven 30 → 101fps | 报告 79 / 17 实测 |
| **按材质排序减少批次** | 500 批 → 8 批，64× | 报告 92 实测 |
| **primus / zink / 换 Vulkan / 关 vsync** | **对 Heaven 无效**（都只动 present 层） | 报告 101 / 105 / 106 实测 |
| 减少每帧状态切换 | 线性收益（118.5µs × 削减次数） | 同上 |

**585/580/525 上无论怎么配都到不了 100fps —— 因为病根在提交器，不在别处。**
**唯一的解法是 515，或者减少配对次数。**

## 6. 一句话

**你说得对，guest 里也是 KDE，显示栈直通进去，两边层数一样 —— 我那个"宿主 KWin + Xwayland"的解释作废。**
