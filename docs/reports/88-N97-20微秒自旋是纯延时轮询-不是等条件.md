# 88 · N97：那个"20µs 自旋"其实是**纯延时轮询**，不含任何条件判断 —— 驱动在按 20µs 粒度轮询队列位置

日期：2026-10-26 14:25
驱动：525.116.03
方法：反汇编 `0x15761b0`（报告 51/52/86 里每对 42 次 `sched_yield` 的落点）

---

## 0. 结论（三条）

1. **`0x15761b0` 不是"等某个条件"，是一个定时轮询原语**：它只读时钟、自旋到 deadline、累加统计，**全程不读任何事件/状态字段**。

```
15761b0: push r14/r13/r12/rbp/rbx; sub $0x10,%rsp
15761bf: test rdi,rdi ; je 15762b0          ; rdi = 对象
15761c8: lea _nv014glcore → rbp             ; vtable
15761cf: rbx = *(obj+0x1300)                ; 子对象（通道/设备）
15761d6: *(obj+0x2c) = 1                    ; 置"在等"标志
15761dd: t0 = clock()          → r14
15761e6: deadline = t0 + 0x14  → r12        ; ★ 20 µs
15761ea: if (rbx && *(rbx+0x2850)==1) → 1576260   ; 另一档：超时 0x17=23µs + 自适应 0x2854/0x2858
15761f8: yield(3)
1576227: loop: rax = clock()
157622d:   if (rax >= deadline) → done
1576232:   if (rbx < rax) → 1576210: 9×pause ; 回到 loop
1576237: done: *(obj+0x6f88) += max(0, rax-t0)   ; 统计累加
157624f: ret
```

   **关键**：循环里只有 `clock()` 与 `pause`，**没有 `cmp` 内存状态、没有 semaphore/timestamp 读取**。
   ⇒ 它是"**睡到 20µs 到了就返回**"，不是"等到某事发生"。

2. **因此驱动的等待模型是"轮询"**：调用者拿到控制权 → 查一次队列位置 → 没进展 → 调这个 20µs 延时 → 再查。
   每对 42 次 yield × ~3µs ≈ 124µs，与 155µs 的 draw 段同量级 ⇒ **一帧的等待被切成 ~42 个 20µs 轮询片**。

3. **与 push buffer 的证据一致**（报告 87）：命令流里没有 `SEMAPHORE_ACQUIRE/RELEASE`，
   所以 GPU 不会主动"等"；GPU 只是**没有及时把"队列消费到哪了"告诉主机**，
   主机只能每 20µs 问一次，问到第 ~8 次（155µs）才看到进展。

## 1. 这条把"等什么"改写成"谁更新队列位置、为什么慢 155µs"

现在整条链是：

```
应用线程：写 bind → 写 draw（各 ~1µs）→ 驱动发现"批次断开"→ 提交该批
驱动：轮询队列位置（每次 20µs 延时 + 查一次），连续 42 次才看到位置推进
      ↑ 这段就是报告 86 的 draw 段 155µs
GPU：util 100% / 37.5W / mem 0% —— 不在算、不在搬数据
```

**⇒ 真正要问的是：GPU 消费完这批之后，把"位置推进"写回主机的动作为什么晚 ~155µs。**

候选（按可测性排序）：

| 候选 | 判据 | 成本 |
|---|---|---|
| A. GPU 写回位置的**同步点**只在特定事件（如帧结束/中断）才发生 | 若把每批之间的 draw 数加大（批次变大），155µs 是否仍按"每批一次"计 | 已有 k 扫描：**是按批计**（报告 83 §2bis）⇒ A 成立的话，位置写回是**每批一次但延迟 155µs** |
| B. 位置写回走 **PCIe posted write + 主机缓存一致性**，被写合并/回刷延迟 | 关掉/打开写合并相关 regkey（已扫 32 位，无） | 高 |
| C. 位置写回依赖**中断**，而中断被合并（报告 23：IRQ 仅 2/s） | 若每批都触发 notify（报告 87：kind=1 每批一次 TRIGGER+NOTIFY），中断合并会把写回推迟到下一次中断窗口 | **与 155µs 的量级不符**（中断合并窗口是 ms 级） |

**A 目前最像**：每批一次 TRIGGER+NOTIFY（报告 87），位置写回跟着这条通知走，
但通知本身不阻塞 GPU；主机侧的 20µs 轮询要等写回可见——155µs ≈ 8 个轮询片。
