# 17 · 515 实测判决：30fps 地板与 dmabuf 抽搐都是 525 独有的回归

> 2026-10-25 12:25
> 起因：用户装回 515 并手动跑出 `FPS 101.4 / Score 2555`（525 是 32.4 / 816），
> 且声明"抽搐在 515 跑高帧率时不存在"。按报告 16 §5 预注册的判据，用**同一探针、同一判据**在 515 上复测。

## 3. 结论

1. **"30fps 地板"是 525 驱动在呈现路径上的回归，不是机器通病。**
   A 配置（同一命令）在 515 上中位 16.67 ms = 恰好 1 个 vblank；在 525 上 33.40 ms = 恰好 2 个 vblank。
   且 A 在 515 上 GPU 处于 P8 空闲态（7% util）——**渲染成本≈0 时 525 仍然每帧吞掉 2 个 vblank**，
   说明多出来的一拍发生在驱动的 swap/交付路径里，不在渲染侧。
   真实场景下同样成立：用户 525 启动器跑分 32.4 fps（Min 23.9），515 同场景锁 60.0 fps。

2. **"60Hz 抽搐"同样是 525 独有的 dmabuf 交付缺陷。**
   525 的 dmabuf 路径 p95/中位 = 2.44~3.65（五分之一帧迟到一拍，偶发 60–100ms）；
   515 同路径 = 1.09（99% 帧落在 16.6±2ms）。用户"抽搐在 515 高帧率时不存在"的观察**被客观数据证实**。
   这也回溯证明了报告 16 §2.1 的方向：抖动源于跨 GPU 交付路径，且是 525 该路径的实现问题。

3. **515 全路径健康**：vsync 开 → 整齐 60fps 锁；`vblank_mode=0` → 92~101fps 且仍然均匀（1.14）。
   用户当前环境（已装 515）没有可感知的呈现问题。

## 4. 疑点排查记录（诚实存档）

- **B 前 12 秒 GPU 仅 1~15% util**：持续采样显示是相机路径轻负载段，后 12 秒爬到 60~82% util / 69~92W，
  帧间隔全程锁 16.6ms。窗口截图（`win_B.png`）确认渲染真实街景。**不是场景未加载。**
- **A 的窗口标题是 "Unigine engine" 而非 "Unigine Heaven Benchmark 4.0"**，全程 7% util / P8：
  无参数直启加载的是裸引擎（无世界）。A 的跨驱动对比仍然有效——**两边用的是同一条命令**（`run_path.sh` 的 primus 分支 `ARGS=""`），
  场景状态一致；525 侧的窗口标题当时未记录，此处按命令同一性推断，标注为推断而非实测。
- **scrot 截 root 全黑**：Xwayland 下 root 窗口不携带合成内容，与 Heaven 渲染无关；
  改用 `import -window <WID>` 抓到真实画面（`win_B.png`）。

## 6. 方法论增量

- **空场景 A/B 是隔离呈现路径的便宜手段**：GPU 空闲（P8）时帧间隔仍被量化到 vblank 整数倍，
  说明量化发生在呈现路径而非渲染路径——用负载探针（nvidia-smi util）佐证场景状态后才能下这个结论。
- **单次 nvidia-smi 采样会骗人**：B 配置前 12 秒 1% util、后 12 秒 82% util，同一场景同一命令。
  判断"场景是否加载"必须持续采样 + 窗口截图，不能看一眼 util 就下结论。
- 报告 16 的 `p95/中位` 判据再次立功：1.06~1.14（515 全路径）vs 2.44~3.65（525 dmabuf）区分度极大。
